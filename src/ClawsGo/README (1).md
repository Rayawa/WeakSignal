# 实验数据分析工具（analyze_data.py）

读取 Arduino 串口日志（`05_Arduino固件/data_acquisition` 的 CSV 输出），一站式完成
标定拟合、盲测校验、噪声底与探测极限、平均时间优化、频率响应与 GUM 不确定度预算，
输出图件和 Markdown 报告。

## 快速开始

```bash
# 1) 无需硬件：生成示例日志并跑通全流程（先看一遍工具输出长什么样）
python3 analyze_data.py --demo

# 2) 分析真实串口日志（从 Arduino 串口监视器保存的文本）
python3 analyze_data.py 串口日志.txt --plot-dir 图件目录 --report 分析报告.md

# 3) 频率响应：按实验顺序给出各测试段驱动频率
python3 analyze_data.py 串口日志.txt --freq-list "0.05,0.1,0.2,0.3,0.5,1.0"

# 4) 盲测偏差分析：对照真实电流
python3 analyze_data.py 串口日志.txt --truth 真实电流.csv

# 5) 用装置实际参数覆盖设计默认值（与仿真参数化共用 JSON）
python3 analyze_data.py 串口日志.txt --params device.json
```

## 串口日志格式（固件默认输出，115200 baud，10 Hz）

```
数据行：  t_ms, V1_mV, V2_mV, P, x_mm, I_nA, U_nV, f_Hz
标定点：  "目标I=... uA, 实测I=... uA, P=..."        （CALSTART 输出）
标定结果："CAL: k=... A/unitP, b=... A..."           （CALFIT 输出）
```

其他行（启动信息、命令回显等）自动忽略。CSV 表头行会被自动跳过。

### 实验数据采集要点（与《04_实验验证方案》一致）

- **标定段**：发送 `CALSTART` 扫描 ±1 µA 共 9 级，`CALFIT` 拟合后工具读标定点重新拟合，
  报告 R²、线性度、残差并与固件结果互校。
- **测量段**：不同实验（空闲、各频率、各注入电流）之间**留 ≥3 s 间隔**（暂停发送），
  工具按时间间隔自动切段。
- **频率响应**：从低到高依次驱动 f = 0.05, 0.1, 0.2, 0.3, 0.5, 1.0 Hz，等幅注入，
  用 `--freq-list` 给出频率表；工具按 FFT 频率自动匹配各段。
- **盲测**：`--truth` 文件（`段序号,真实电流_µA`，每行一个）给出各段真实电流，
  工具逐段比较测量幅值并给出偏差百分比。

## 输出内容

| 项目 | 说明 | 验收参考 |
|---|---|---|
| 后级标定 | k、b、R²、线性度、残差表 | R² > 0.999，线性度 < 1% |
| 噪声底 | σ(P) → σ(I)，单次 3σ 探测极限 | 仿真预期 ~200 pA / ~0.6 nA |
| 平均时间优化 | 分块平均 σ 曲线，最优平均时间 | 仿真预期 ~8 s → ~13–20 pA |
| 频率响应 | 实测 |H(f)| vs 理论二阶模型 | f0 ≈ 0.5 Hz，频带 ≤ 0.1 Hz |
| 盲测偏差 | 各段测量 vs 真实电流 | 相对偏差 < 5% |
| GUM 不确定度 | 分量表 + 合成 + 扩展 (k=2) | u_c ≈ 2.6%，U ≈ 5.2% |

## 参数文件（device.json）

与 `03_仿真与数据验证` 的参数化仿真共用同一 JSON 格式（缺省用设计默认值）：

```json
{
  "N1": 50, "A1": 1.0e-4, "N2": 100, "A2": 4.0e-4,
  "Bmag": 0.1, "k": 1.0e-6, "J": 1.0e-7, "D": 1.0,
  "L": 0.02, "R_loop": 100.0, "zeta": 0.3
}
```
